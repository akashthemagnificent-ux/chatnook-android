# ChatNook — v2 Roadmap (post-baseline)

Status: active
Started: 2026-11-07
Supersedes: `2026-10-25-discord-parity-v1.md` (kept as history; all of its boxes are
either done or folded into a phase below).

## Where the project actually stands (verified 2026-11-07)

- Live Supabase project: schema v1+v2 applied. Anonymous sign-in on, email autoconfirm on.
- Backend verified end-to-end with three real accounts: profile bootstrap, create guild,
  default `#general`, invite create/join, message read/write, reaction, DM idempotency,
  and RLS isolation (outsider cannot read guild, channel or DM).
- Storage buckets `avatars`/`banners`/`emojis` accept authenticated uploads and serve
  public reads.
- Release APK builds in CI, runs minified, and completes a real HTTPS round trip.
- Device loop: emulator `atd35` + `agent-device` replay (`tools/chatnook-signin.ad`).

So the foundation is real. What is missing is everything that makes a chat app feel
finished to a non-technical user.

## Working rules for every phase

1. One phase = one branch = one PR. CI must be green before merge.
2. Every phase ends with: unit tests for its pure logic, a release build, and a device
   pass on the emulator against the live backend.
3. No feature ships without its empty / loading / error state.
4. New user-visible strings go in `strings.xml`.
5. If a phase needs something only the human can provide (Firebase, keystore, SMTP),
   it is listed under that phase and requested at its start, not before.

## Phase 1 — Message experience (must ship before friends install)

The chat screen currently loads 50 messages once, force-scrolls on every change, and
waits for the realtime echo before showing your own message. That is the first thing
users will notice.

- [ ] Keyset pagination: load 50 older messages when scrolled near the top; keep the
      viewport anchored on the message that was at the top.
- [ ] Stop auto-scrolling when the user is reading history; show a "jump to latest"
      pill with an unread count instead.
- [ ] Optimistic send: render immediately as pending, reconcile on ack, mark failed
      with retry. Dedupe by id against the realtime insert.
- [ ] Day separators; 12/24h from the system setting; relative time for today.
- [ ] Delete confirmation dialog.
- [ ] Markdown-lite: **bold**, *italic*, ~~strike~~, `code`, ```blocks```, links,
      @mentions highlighted, custom `:emoji:` resolved to images.
- [ ] Tests: page merge/dedupe, grouping, markdown parser, time formatter.

Verify: two accounts in two emulator users; A sends while B reads history; B stays put;
B taps the pill; A's message appears without a refresh; airplane mode marks send failed
and retry succeeds.

## Phase 2 — Media

- [ ] Image attachments from the composer (camera + gallery), downscaled to ≤1600px and
      re-encoded under 1 MB before upload, with progress and cancel.
- [ ] Inline attachment rendering (single, grid for 2-4), tap for fullscreen pager.
- [ ] Upload guards shared with avatar/banner/emoji paths (type, size, failure message).
- [ ] Tests: downscale target, MIME/extension guard, attachment JSON mapping.

## Phase 3 — Presence and unread

- [ ] Typing indicator (realtime broadcast, throttled, 5s expiry).
- [ ] Read states: `last_read_message_id` per channel, unread badges in the channel
      list, mention count, mark-read on open and on scroll-to-bottom.
- [ ] Online presence dots from Supabase Realtime presence.
- [ ] Tests: unread reducer, mention detection.

## Phase 4 — People

- [ ] Member list grouped by role, tap for a profile sheet (banner, badges, status).
- [ ] DM list in the rail: avatar, name, last message, unread; start DM from a member.
- [ ] DM thread reuses the chat screen (no duplicated message code).
- [ ] Tests: DM list ordering/dedupe, member grouping.

## Phase 5 — Server management

- [ ] Server settings: rename, icon upload, delete (owner only, typed confirmation).
- [ ] Channel management: create, rename, topic, delete, reorder (drag or up/down).
- [ ] Roles: create/edit name, colour, permission bits; assign to members.
- [ ] Permission resolver (Discord algorithm) enforced in UI; RLS stays the real gate.
- [ ] Invite management: list, revoke, expiry/uses.
- [ ] Tests: permission truth table (security-critical), invite validation.

## Phase 6 — Notifications (needs human: Firebase)

- [ ] Firebase project + `google-services.json`; FCM SDK; token registration.
- [ ] Edge Function on message insert → push to members without a covering read state.
- [ ] Notification channel, deep link to the channel, foreground suppression.
- [ ] Per-guild mute and per-channel notification level.
- [ ] Tests: payload builder, suppression logic.

## Phase 7 — Nitro polish (the differentiator)

- [ ] Profile card redesign: banner header, gradient wash, decoration ring, badges,
      status, member-since, mutual servers.
- [ ] Animated avatar/banner (GIF/WebP) with a still fallback.
- [ ] Theme editor: preset gradients + custom two/three-stop picker with texture.
- [ ] Custom emoji picker in the composer and the reaction sheet.
- [ ] Design tokens, motion, haptics, dark-first theme, accessibility pass.

## Phase 8 — Release hardening (needs human: keystore password)

- [ ] Signed release APK from CI secrets; versionCode from run number; GitHub Release
      with the APK attached and a short changelog.
- [ ] Update check: in-app prompt when a newer release exists.
- [ ] Crash/ANR visibility without a paid service (local crash log + optional share).
- [ ] Backend keepalive (scheduled ping) and quota watch.
- [ ] Friend-facing install guide, privacy note, and a rollback path.
- [ ] Soak test: 3 accounts, 500 messages, 24h idle, verify reconnect and paging.
