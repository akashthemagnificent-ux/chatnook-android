# ChatNook — v2 Roadmap (post-baseline)

Status: active
Started: 2026-11-07
Supersedes: `2026-10-25-discord-parity-v1.md` (kept as history; all of its boxes are
either done or folded into a phase below).

## Where the project actually stands (verified 2026-11-07)

- Live Supabase project: schema v1+v2 applied. Anonymous sign-in on, email autoconfirm on.
- Backend verified end-to-end with three real accounts: profile bootstrap, create guild,
  default `#general`, invite create/join, message read/write, reaction, DM idempotency,
  and RLS isolation (outsider cannot read guild, channel or DM).
- Storage buckets `avatars`/`banners`/`emojis` accept authenticated uploads and serve
  public reads.
- Release APK builds in CI, runs minified, and completes a real HTTPS round trip.
- Device loop: emulator `atd35` + `agent-device` replay (`tools/chatnook-signin.ad`).

So the foundation is real. What is missing is everything that makes a chat app feel
finished to a non-technical user.

## Working rules for every phase

1. One phase = one branch = one PR. CI must be green before merge.
2. Every phase ends with: unit tests for its pure logic, a release build, and a device
   pass on the emulator against the live backend.
3. No feature ships without its empty / loading / error state.
4. New user-visible strings go in `strings.xml`.
5. If a phase needs something only the human can provide (Firebase, keystore, SMTP),
   it is listed under that phase and requested at its start, not before.

## Phase 1 — Message experience (must ship before friends install)

Before this phase the chat screen loaded 50 messages once, force-scrolled on every
change, and waited for the realtime echo before showing your own message — the first
thing users would have noticed.

- [x] Keyset pagination: load 50 older messages when scrolled near the top; keep the
      viewport anchored on the message that was at the top.
- [x] Stop auto-scrolling when the user is reading history; show a "jump to latest"
      pill with an unread count instead.
- [x] Optimistic send: render immediately as pending, reconcile on ack, mark failed
      with retry. Dedupe by id against the realtime insert.
- [x] Day separators; 12/24h from the system setting; relative time for today.
- [x] Delete confirmation dialog.
- [x] Markdown-lite: **bold**, *italic*, ~~strike~~, `code`, ```blocks```, links,
      @mentions highlighted, custom `:emoji:` resolved to images.
- [x] Tests: page merge/dedupe, grouping, markdown parser, time formatter.

Shipped in PR #4.

Verify (done on device): fresh account → create server → open #general → send → cold
restart → message still loads (this is what caught the ambiguous-embed bug).
Verify (still open): two accounts side by side; airplane-mode failure → retry.

## Phase 2 — Media

- [x] Image attachments from the composer via the system photo picker; downscaled to
      ≤1600px, EXIF-rotated and re-encoded under 1 MB before upload.
- [x] Inline attachment rendering; tap opens a fullscreen viewer.
- [x] Upload guards: bucket limit + MIME allow-list, and `send_message` refuses a row with
      no URL or one over 8 MB. Upload and message insert are one transaction so Realtime
      never delivers a picture-less message.
- [x] Tests: downscale target, sample size, attachment JSON mapping, aspect clamp.
- [ ] Deferred on purpose: camera capture, and 2-4 image grids — the composer sends one
      image per message for now. Add both together when someone actually asks.

Shipped in PR #5. Backend: `supabase/migrations/0003_attachments.sql` (bucket + policies +
`send_message`), applied to the live project via `tools/db.py`.

## Phase 3 — Presence and unread

- [x] Typing indicator: Realtime broadcast on `typing-<channel>`, throttled to one ping
      per 3 s, dropped 5 s after the last ping. No table, no rows.
- [x] Read states: `last_read_message_id` per channel written when the newest row is on
      screen; unread badges in the channel list, `@n` for mentions; the open channel is
      masked locally so a refresh cannot flash its badge back.
- [x] Online presence dots from Realtime presence, one key per account; the chat header
      shows the online count and who is typing.
- [x] Mention detection (`@name` as a whole word, shared with the server's regex) tints
      the message row.
- [x] Tests: unread reducer, mention boundaries, badge caps.

Shipped in PR #6. Backend: `supabase/migrations/0004_unread.sql` (`channel_unread_counts`,
`read_states` added to the realtime publication).

Device notes: supabase-kt only joins with presence if a presence callback is registered
before `subscribe()`, and `track()` needs the join acknowledged — both are easy to get
wrong silently.

## Phase 4 — People

- [x] Member list grouped by role: owner first, then roles by position, then everyone
      else, alphabetical inside. Online dot from the presence flow.
- [x] Profile sheet on tap: banner, avatar, handle, custom status, badges, and a Message
      button that opens (or reuses) the DM.
- [x] DM list behind the rail's home button: avatar, name, last message preview, unread.
- [x] DM thread reuses `ChatScreen`, so paging, typing, attachments and mark-read work
      unchanged; only the `#`/`@` prefix and the composer hint differ.
- [x] Tests: member grouping, DM ordering and dedupe.

Shipped in PR #7. Backend: `supabase/migrations/0005_people.sql` — `dm_summaries()`, and
`channel_unread_counts` now covers every channel the user can reach when the guild is null.

## Phase 5 — Server management

- [ ] Server settings: rename, icon upload, delete (owner only, typed confirmation).
- [ ] Channel management: create, rename, topic, delete, reorder (drag or up/down).
- [ ] Roles: create/edit name, colour, permission bits; assign to members.
- [ ] Permission resolver (Discord algorithm) enforced in UI; RLS stays the real gate.
- [ ] Invite management: list, revoke, expiry/uses.
- [ ] Tests: permission truth table (security-critical), invite validation.

## Phase 6 — Notifications (needs human: Firebase)

- [ ] Firebase project + `google-services.json`; FCM SDK; token registration.
- [ ] Edge Function on message insert → push to members without a covering read state.
- [ ] Notification channel, deep link to the channel, foreground suppression.
- [ ] Per-guild mute and per-channel notification level.
- [ ] Tests: payload builder, suppression logic.

## Phase 7 — Nitro polish (the differentiator)

- [ ] Profile card redesign: banner header, gradient wash, decoration ring, badges,
      status, member-since, mutual servers.
- [ ] Animated avatar/banner (GIF/WebP) with a still fallback.
- [ ] Theme editor: preset gradients + custom two/three-stop picker with texture.
- [ ] Custom emoji picker in the composer and the reaction sheet.
- [ ] Design tokens, motion, haptics, dark-first theme, accessibility pass.

## Phase 8 — Release hardening (needs human: keystore password)

- [ ] Signed release APK from CI secrets; versionCode from run number; GitHub Release
      with the APK attached and a short changelog.
- [ ] Update check: in-app prompt when a newer release exists.
- [ ] Crash/ANR visibility without a paid service (local crash log + optional share).
- [ ] Backend keepalive (scheduled ping) and quota watch.
- [ ] Friend-facing install guide, privacy note, and a rollback path.
- [ ] Soak test: 3 accounts, 500 messages, 24h idle, verify reconnect and paging.
